### 1. Today's tracker objective

**Area:** Create API  
**Exact learning topic:** Implement `POST /api/v1/habits`

Today we will implement one endpoint that creates a habit and stores it in the local MySQL database.

- Bind the request to a Request DTO.
- Pass the request to the Service layer.

## 2. What are we building?

The client sends a request such as:

```http
POST /api/v1/habits
Content-Type: application/json
```

```json
{
  "name": "Read Java",
  "description": "Read Java for 30 minutes every day"
}
```

The backend saves the habit in MySQL and responds with:

```http
HTTP/1.1 201 Created
Content-Type: application/json
```

```json
{
  "id": 1,
  "name": "Read Java",
  "description": "Read Java for 30 minutes every day"
}
```

The `id` is generated by the database/JPA mapping. The client does not send it when creating a new habit.

## 3. Understand the complete request flow

```text
Client / Postman
       |
       | POST /api/v1/habits + JSON
       v
HabitController
       |
       | receives HabitRequest
       v
HabitService
       |
       | creates a Habit entity
       v
HabitRepository
       |
       | save(habit)
       v
MySQL database
       |
       | saved row, including generated id
       v
HabitService
       |
       | maps saved entity to HabitResponse
       v
HabitController
       |
       | HTTP 201 + JSON response
       v
Client / Postman
```

Why use these layers?
- The Controller handles HTTP concerns.
- The Service owns the use-case/business logic.
- The Repository handles persistence.
- DTOs define the API input and output.
- The Entity represents persisted data.

## 5. Request DTO – `HabitRequest`

The Request DTO contains the fields the client is allowed to submit when creating a habit.

Create or verify:

**File:** `dto/HabitRequest.java`

```java
package com.habitflow.backend.dto;

public class HabitRequest {

    private String name;
    private String description;

    public HabitRequest() {
    }

    public HabitRequest(String name, String description) {
        this.name = name;
        this.description = description;
    }

    public String getName() {
        return name;
    }

    public void setName(String name) {
        this.name = name;
    }

    public String getDescription() {
        return description;
    }

    public void setDescription(String description) {
        this.description = description;
    }
}
```

Important points:
- The client sends `name` and `description`.
- The client does not send the generated database `id`.
- A no-argument constructor and getters/setters allow Jackson to bind JSON to this ordinary Java object in the usual Spring Boot configuration.
- We are deliberately not adding validation annotations today. Those belong to Week 4.

## 6. Response DTO – `HabitResponse`

The Response DTO defines the data returned after the habit is saved.

**File:** `dto/HabitResponse.java`

```java
package com.habitflow.backend.dto;

public class HabitResponse {

    private Long id;
    private String name;
    private String description;

    public HabitResponse() {
    }

    public HabitResponse(Long id, String name, String description) {
        this.id = id;
        this.name = name;
        this.description = description;
    }

    public Long getId() {
        return id;
    }

    public void setId(Long id) {
        this.id = id;
    }

    public String getName() {
        return name;
    }

    public void setName(String name) {
        this.name = name;
    }

    public String getDescription() {
        return description;
    }

    public void setDescription(String description) {
        this.description = description;
    }
}
```

Why return a Response DTO?
- It keeps the API response separate from the database entity.
- It lets the backend decide which fields are exposed.
- It avoids making the API contract depend directly on the persistence model.

```java
        return name;
    }

        this.name = name;
    }

    public String getDescription() {
        return description;
    }

    public void setDescription(String description) {
        this.description = description;
    }

```

## 8. Repository – `HabitRepository`

Reuse the repository created in Week 2.

**File:** `repository/HabitRepository.java`

```java
package com.habitflow.backend.repository;

import com.habitflow.backend.entity.Habit;
import org.springframework.data.jpa.repository.JpaRepository;

public interface HabitRepository extends JpaRepository<Habit, Long> {
}
```

`JpaRepository<Habit, Long>` tells Spring Data:
- `Habit` is the entity type.
- `Long` is the type of the entity's primary key.

The inherited `save()` method is what we need today. Spring Data JPA provides the implementation at runtime; you do not write the SQL insert yourself.

## 9. Service – `HabitService`

The Service coordinates the create-habit use case.

**File:** `service/HabitService.java`

```java
package com.habitflow.backend.service;

import com.habitflow.backend.dto.HabitRequest;
import com.habitflow.backend.dto.HabitResponse;
import com.habitflow.backend.entity.Habit;
import com.habitflow.backend.repository.HabitRepository;
import org.springframework.stereotype.Service;

@Service
public class HabitService {

    private final HabitRepository habitRepository;

    public HabitService(HabitRepository habitRepository) {
        this.habitRepository = habitRepository;
    }

    public HabitResponse createHabit(HabitRequest request) {

        // 1. Convert incoming request data into an entity.
        Habit habit = new Habit();
        habit.setName(request.getName());
        habit.setDescription(request.getDescription());

        // 2. Save the entity in the database.
        Habit savedHabit = habitRepository.save(habit);

        // 3. Convert the saved entity into the API response DTO.
        return new HabitResponse(
                savedHabit.getId(),
                savedHabit.getName(),
                savedHabit.getDescription()
        );
    }
}
```

### Understand the important lines

**`@Service`**

Marks this class as a Spring-managed service component. Component scanning can discover it and register it as a bean.

**`private final HabitRepository habitRepository;`**

Declares the dependency. `final` means the field must be assigned during construction and cannot later be reassigned.

**Constructor injection**

```java
public HabitService(HabitRepository habitRepository) {
    this.habitRepository = habitRepository;
}
```

Spring supplies the repository bean when it creates the service bean. This is constructor injection, which you studied on Week 3 Day 2.

**Create the entity**

```java
Habit habit = new Habit();
habit.setName(request.getName());
habit.setDescription(request.getDescription());
```

The incoming DTO is not itself a JPA entity. We copy its data into an entity.

**Save**

```java
Habit savedHabit = habitRepository.save(habit);
```

The repository asks JPA/Hibernate to persist the entity. With an identity-generated primary key, the saved entity returned by `save()` contains the generated ID after persistence.

**Map the response**

```java
return new HabitResponse(
        savedHabit.getId(),
        savedHabit.getName(),
        savedHabit.getDescription()
);
```

Use the saved entity, not the original unsaved object, because the saved entity has the generated ID.

## 10. Controller – `HabitController`

The Controller exposes the HTTP endpoint.

**File:** `controller/HabitController.java`

```java
package com.habitflow.backend.controller;

import com.habitflow.backend.dto.HabitRequest;
import com.habitflow.backend.dto.HabitResponse;
import com.habitflow.backend.service.HabitService;
import org.springframework.http.HttpStatus;
import org.springframework.http.ResponseEntity;
import org.springframework.web.bind.annotation.*;

@RestController
@RequestMapping("/api/v1/habits")
public class HabitController {

    private final HabitService habitService;

    public HabitController(HabitService habitService) {
        this.habitService = habitService;
    }

    @PostMapping
    public ResponseEntity<HabitResponse> createHabit(
            @RequestBody HabitRequest request) {

        HabitResponse response = habitService.createHabit(request);

        return ResponseEntity
                .status(HttpStatus.CREATED)
                .body(response);
    }
}
```

### Understand the annotations and return type

- `@RestController`: declares a REST controller. Return values are written to the HTTP response body.
- `@RequestMapping("/api/v1/habits")`: sets the common URL path for this controller.
- `@PostMapping`: maps HTTP POST requests to this method. Because the class already has the base path, the method's path is empty.
- `@RequestBody`: asks Spring to read the JSON request body and convert it into a `HabitRequest`.
- `ResponseEntity<HabitResponse>`: gives control over both the response body and HTTP status.
- `HttpStatus.CREATED`: represents HTTP status `201 Created`.

The final endpoint is:

```text
POST http://localhost:8080/api/v1/habits
```

## 12. Common problems and how to investigate

| Symptom | What to check |
|---|---|
| `404 Not Found` | Confirm the URL, `@RequestMapping`, `@PostMapping`, and application port. |
| `405 Method Not Allowed` | Confirm that the request method is POST. |
| `400 Bad Request` | Check that the request body is valid JSON and property names match the DTO. |
| `415 Unsupported Media Type` | Set `Content-Type: application/json` or select JSON in Postman. |
| `500 Internal Server Error` | Read the server console stack trace; check entity mapping, database connectivity, and table/column names. |
| Database connection refused | Confirm MySQL is running and the datasource URL/credentials are correct. |
| Table does not exist | Check the selected database and your JPA schema-generation/migration setup. |
| Response ID is null | Confirm the entity's `@Id` and `@GeneratedValue` mapping and use the entity returned by `save()`. |
| Duplicate class/package errors | Reuse the classes from previous days; do not create duplicate copies. |

## 15. Interview questions and sample answers

### 1. What is the purpose of a POST API?

A POST API is commonly used to submit data to a server to create a resource or trigger processing. In HabitFlow, `POST /api/v1/habits` creates a new habit.

### 2. What is the role of `@RequestBody` in Spring Boot?

`@RequestBody` tells Spring to read the HTTP request body and deserialize it into the method parameter type. For example, JSON can be converted into a `HabitRequest` object.

### 3. Why do we use a Request DTO?

A Request DTO defines the fields accepted from the client. It prevents the API from accepting every field in the persistence entity and keeps the external request contract separate from the database model.

### 4. Why should the Controller not contain all business logic?

The Controller should focus on HTTP request and response handling. Moving use-case logic into a Service improves separation of concerns, readability, reuse, and testability.

### 5. What is the purpose of the Service layer?

The Service layer coordinates application operations. In this create flow, it converts the request into an entity, calls the repository to save it, and maps the saved entity to a response DTO.

### 6. What does `JpaRepository` provide?

`JpaRepository` provides common persistence operations such as `save`, `findById`, `findAll`, and `deleteById`, along with additional JPA-related functionality. We use `save` in today's create API.

### 7. What does `save()` do in Spring Data JPA?

`save()` persists a new entity or updates an existing entity according to the entity's persistence state and identifier. It returns the saved entity instance.

### 8. Why use the entity returned by `save()`?

The returned entity represents the saved state. It can contain a generated primary key, which we need to include in the create response.

### 9. What is the difference between `@Controller` and `@RestController`?

`@RestController` combines `@Controller` and `@ResponseBody` behavior. It is commonly used for REST APIs because method return values are written to the response body rather than treated as view names.

### 10. Why return HTTP 201 Created?

`201 Created` indicates that the request successfully created a resource. It is an appropriate status for this HabitFlow POST endpoint.

### 11. What is `ResponseEntity`?

`ResponseEntity` represents the complete HTTP response, allowing the application to specify the response body, status code, and headers.

### 12. Explain the request flow for `POST /api/v1/habits`.

The client sends JSON. Spring binds it to `HabitRequest`. The Controller calls the Service. The Service creates a `Habit` entity and calls `HabitRepository.save()`. The saved entity is mapped to `HabitResponse`, which the Controller returns with HTTP 201.
